# AI Agent 全局开发规范

一份经过多轮评审与迭代打磨的 AI 编码 Agent 全局提示词（AGENTS.md），附一份可视化解析页，说明它的设计逻辑，以及在各种真实情况下 Agent 会如何表现。

## 规范解决什么问题

AI 编码助手最常见的四类失控：**擅自行动、无限瞎试、假装完成、破坏用户已有工作**。这份规范用四条互相咬合的机制应对：

- **五级优先级链** —— P0 安全 > P1 用户要求 > P2 任务正确 > P3 项目规范 > P4 Agent 偏好。规则冲突时有唯一裁决，不靠模型临场发挥；"最小改动"这类好习惯放在 P4，意味着用户随时可以合理覆盖
- **双向行动边界** —— 白名单内的低风险操作直接做、不请示；歧义/不可逆/影响外部环境必须确认；中间地带先自行查证，不把轻微不确定甩给用户
- **3 次止损** —— 同一根因连续 3 次实质修复仍未通过验证，强制停止并汇报根因、已试方案与阻塞点，禁止无限重试
- **诚实汇报流程** —— 十项完成标准 + 固定汇报模板，强制区分"已完成 / 已验证 / 未完成 / 待用户操作 / 存在风险"，测试未通过不得声称修复

## 场景速览

| 你说 / 遇到 | Agent 会 |
|---|---|
| "把那个目录清掉"（范围模糊） | 不猜范围，附推荐方案、备选与不可逆点后再确认 |
| "把 SSL 校验关掉就能导数据" | 直接拒绝（P0，用户要求也不能突破），给安全替代方案 |
| npm install 失败 | 读全报错 → 分类根因逐级处理；绝不改成 `latest`、不静默 `--force`、不删 Lockfile |
| 同一个测试修了 3 次还不过 | 停止瞎试，交止损报告，等你指方向 |
| 工作区有你改到一半的文件 | 认定为你的资产，只做增量修改，绝不覆盖或回滚 |
| 顺手发现了别的问题 | 只修当前任务，其他问题记录并告知，不扩大战线 |

更多 12 个完整场景推演（含每个场景"为什么这样设计"）见解析页。

## 如何使用

1. 复制 `AGENTS.md` 全文到你所用 AI 编码工具的全局规则位置，例如 ZCode 的 `~/.zcode/AGENTS.md`、Claude Code 的 `CLAUDE.md`、Cursor 的 `.cursorrules`，或项目根目录的 `AGENTS.md`
2. 按自己的实际环境修改 §2（操作系统与 Shell，默认 Windows + Git Bash）和 §2.3（语言偏好，默认沟通/注释/commit 中文、代码英文）
3. 建议与平台自身的权限确认机制配合使用——提示词约束行为偏好，不提供强制执行；真正的高危防线是平台权限层 + Git 可回滚性

## 迭代说明

从最初的 28 节版本出发，经过四轮评审迭代：补充规则优先级链与自主/确认边界 → 合并四个重复的禁止章节 → 增加失败止损机制与确认时的决策上下文格式 → 去重压缩至 14 节。每条修订的检验标准都是同一个问题：**这条规则在真实场景里会如何改变 Agent 的行为？**
